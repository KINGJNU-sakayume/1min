# 현실성 보강 조사: 실제 흐름·문구·수치

작성일: 2026-10-17 · `pain-points-and-references.md`의 후속. 목적은 게임 화면이 **"진짜 같다"**는 느낌을 주는 구체 디테일(단계, 버튼 이름, 제한시간, 오류 상황의 말투)을 모으는 것이다.

라벨: **[확인]** 공식 공지·언론·학교 문서 / **[2차]** 블로그·후기·SNS(사실과 다를 수 있음) / **[기억]** 내 사전지식이며 이번에 출처로 확인하지 못함 / **[미확인]**.
출처 ID는 이어서 S47부터 쓴다. (S1–S46은 기존 보고서 §10)

한계: 예매처·학교 사이트 화면을 직접 캡처하지 못했다. 로그인이 필요하거나 동적 렌더링이라 가져온 것은 가이드 글·언론·공지의 **설명**이다. 화면 배치(레이아웃) 정보는 대부분 [기억] 또는 [2차]이며, 구현 전에 **사용자가 실제 화면을 한 번씩 보고 스크린샷 메모**를 남기는 것이 가장 정확하다 (→ `plan/prototype-scope.md` 선행 작업).

## 1. 티켓팅 (공연 예매) — 실제 단계

[2차 S54] 예매 화면 단계와 버튼 이름(가이드 글 기준):

| 순서 | 단계 | 버튼/문구 | 비고 |
|---|---|---|---|
| 0 | 로그인·본인인증 | "로그인" | 예매 전에 끝내 둠 |
| 1 | 날짜/회차 선택 → **"예매하기"** | "예매하기" | 이 버튼은 **하나만** 눌러야 함. 경쟁이 심하면 대기번호가 뜸 |
| 2 | **안심예매 문자 입력** | "입력완료" | 여기서 실수로 나가거나 F5를 누르면 다시 기다림 |
| 3 | 좌석 선택 | **"좌석선택완료"** | 기본 1층, 2층 구역을 누르면 좌석 창이 바뀜 |
| 4 | 가격/할인 선택 | "다음 단계" | 기본가 수량이 0매 → 1매로 바꿔야 함 |
| 5 | 배송/주문자 확인 | "다음 단계" | 생년월일 6자리 입력, 연락처·이메일·수령 방법 |
| 6 | 결제 | "다음 단계" → 취소수수료·취소기한 동의 → **"결제하기"** | 무통장입금 선택 가능 |

게임 시사점: 정각 클릭 이후에도 **단계가 6개나 남아 있다**는 것 자체가 고통이다. 짧은 판에서는 2~3단계를 한 화면 전환으로 압축하되 **"수량 0매를 1매로 바꿔야 하는" 류의 함정 단계**를 유지하면 현실감이 산다.

[확인/2차 S48] 좌석 충돌 시 화면에 **"이미 선택된 좌석입니다"**가 뜬다는 정리가 있고, 다른 구역으로 바로 재시도하라는 조언이 따른다. 사용자가 처음 제시한 밈과 일치한다. 같은 글에서 정리한 다른 문구 예: "예매 정보가 올바르지 않습니다". [2차]

[2차 S48] 대기열: 새로고침·뒤로가기·창 닫기를 하면 순서가 처음으로 돌아간다. VPN은 봇으로 차단될 수 있다는 조언. 결제 제한 타이머는 있으나 길이는 명시 안 됨.

[2차 S58] 한 멜론티켓 팁 글(SNS 게시물)은 좌석을 한 번 선택하고 넘어가면 **5분간 점유**되고, 그 안에 예매를 완료하지 않으면 점유가 풀린다고 설명한다. 그래서 20시 티켓팅이면 20시 5분부터 풀린 자리가 나온다는 취켓팅 요령이 이어진다. 무통장입금 기한은 예매 다음 날 23:59라는 설명도 있다. (예매처별로 다를 수 있음)

[2차 S48/S54] 무통장입금 예약은 입금 기한 후 좌석이 풀린다. 게임에서는 "결제는 무통장입금이 낫다"는 커뮤니티 속설을 선택지 함정으로 쓸 수 있다.

[2차 S49 — 2016년 게시물, 현재와 다를 수 있음] 인터파크 **예매대기** 서비스: 매진 공연에서 이미 팔린 좌석을 골라 대기를 걸어두고(1,000원, 카드만), 취소가 나오면 문자 알림이 오며 **6시간 이내 결제**해야 한다. 실패하면 1,000원 환불. 한 자리당 최대 5명 대기. → 취켓팅 보너스 라운드의 **현실 기반 변형**으로 쓸 만하다. 현재 정책은 [미확인].

[확인] 인터파크 공연 공지에는 **"1개의 계정으로는 1개의 대기열 순번만"**, 다중 기기·브라우저로 대기열을 만들면 기존 대기열이 종료된다는 문구가 있다. (기존 보고서 S4)

[미확인] 인터파크 공식 FAQ(좌석 선점 시간 등)는 리다이렉트되어 내용을 읽지 못했다 (`help.interpark.com` → 다른 도메인). 선점 시간 수치는 예매처·공연별로 다르다고 가정한다.

## 2. 대학 수강신청 — 실제 증상과 문구

[확인 S55: 연세춘추, 2023학년도 1학기 사태] 추가수강신청 첫날: 8시 30분 접속 학생이 8시 40분부터 담기·검색·수업계획서 조회가 어려웠고, 9시에 누른 신청 버튼의 결과를 **약 1시간** 알 수 없었다. 대기번호 과목 취소 시 **"수강신청 기간이 아닙니다"** 문구, 희망 버튼 누르면 **무한 로딩**. 학교가 당일 일정을 두 번 번복하고 당일 신청 결과를 무효 처리했다. 다른 날에는 **"송도 RC 대상자는 신촌과목 수강이 불가능합니다"**처럼 담기는 되는데 신청 버튼에서 막히는 오류.

[확인 S56: 채널PNU] 로그인에만 **10분**. 정각에 **"수강신청 기간이 아닙니다!"** 팝업이 약 **5분** 동안 계속 떠서 전공 신청이 모두 실패했다는 증언. 에러창이 네 번쯤 떴다는 응답. 대기 순번 숫자가 늘어나는 **표시 오류**(정원 초과 없이 대기 순번이 증가)가 있었고 학교는 화면 순번이 실제 데이터와 달랐다고 설명. 신입생 수강신청이 로그인 장애로 **1시간 30분** 연기된 사례.

[확인 S25 → 기존] 성적공시일 서버 다운 질의응답: 서버 증설·부하 테스트가 반복 요구됨.

[확인 S59: 고려대 학사 안내] 단계 구조: 수강희망과목 등록(담아두기) → 수강신청 → 수강정정 → 수강포기. 수강희망과목 등록 인원이 **정원 이하면 모두 신청 처리**, 초과하면 **정원의 20%만 우선순위 추첨**. 수강신청 기간에는 담아두기를 못 한다. **시간이 겹치는 과목은 신청 불가**. 학점은 기본 1~19학점. (학교마다 다름)

[확인 S60: 조선대 공지] 학년별 정원 제한이 풀려 일부 과목에서 초과 인원이 발생했고, 초과 인원은 신청 시각 순으로 일부 과목에서 제거됐으며 문자로 개별 안내됐다. 3·4학년 동시 오픈 계획을 안정성 우려로 4학년 1시간 앞당긴 사례.

게임 시사점
- 대표 팝업 문구는 **"수강신청 기간이 아닙니다!"** 계열 — 정각 직전·직후에 뜨는 것이 현실적이다 (정각 판정과 서버 지연 카드 결합).
- **무한 로딩 + 결과를 모르는 상태**가 실제의 핵심 공포다. 신청 버튼을 누른 뒤 "결과 확인 중…"이 길게 이어지고 **나중에 실패로 확정**되는 카드를 만들 수 있다.
- **"담기는 되는데 신청에서 막힘"** 패턴 (자격 오류): 장바구니 성공 → 신청 시 사유 팝업.
- 화면 대기 순번이 줄지 않고 늘어나는 **표시 오류**는 코미디에 좋다.

## 3. 명절 기차표 — 실제 규칙과 숫자

[2차 S52: 모바일웹 예매 가이드, 날짜는 과거 글] 코레일 명절 예매:
- 명절 예매 전용 페이지는 앱 로그인과 **별도로 로그인**해야 한다. 접속이 몰리면 **"접속대기인원 수"** 화면, 순서가 되면 로그인 화면으로 자동 전환.
- 메인에 두 버튼: **"명절승차권 예약"** / **"승차권 예매"**.
- 예약 방식 두 가지: 잔여석 조회 후 예약 / 특정 열차·시간대 바로 예약(시간대로 지정하면 가장 가까운 좌석 있는 열차를 자동 배정).
- **예매 제한시간 3분은 로그인 이후부터 계산**. 3분이 지나면 예약 여부와 무관하게 **강제 로그아웃**.
- 예약 화면에 **예약요청 횟수와 남은 예약 가능 시간이 빨간색**으로 표시. (과거 글: 예약요청 6회 초과 시 강제 로그아웃. 2025 추석부터 해제 예정이라는 설명 — [2차], 현행 규칙은 [미확인])
- 한도: 회원 1인 1회 6매, 왕복 12매. "이미 예약한 승차권과 중복" 안내가 뜰 수 있음.
- 로그인 비밀번호는 **특수문자·숫자 포함 8자리 이상**, 역 발매기용 4자리 숫자는 쓸 수 없음. 아이디는 멤버십 번호 10자리. → 로그인 단계에서 막히는 현실적 함정.
- 돌아오는 편 예약 시 **가는 편 날짜를 그대로 두는 실수**가 잦음. → "날짜 선택" 함정 카드.
- 예약만으로 끝이 아니고 **기한 내 결제**해야 하며 미결제 시 자동 취소.

[확인 S50: 뉴스1, 2022-08] 코레일톡 승차권 **결제 대기시간이 20분 → 10분**으로 조정(2022-08-10 시행), **출발 임박(20분 전부터)은 5분**.

[2차 S51: 가이드] 대기 화면을 벗어나면 **순번이 맨 뒤로** 밀림. 화면이 하얗게 멈추면 **브라우저 새로고침이 아니라 페이지 하단의 [새로고침] 버튼**을 쓰라는 조언. 메신저·포털 인앱 브라우저에서는 정상 동작하지 않을 수 있고, 여러 탭이 오류로 대기열에서 이탈시킬 수 있다.

[2차 S53: 2026 추석 일정 요약] 통합회원 로그인 필요, 앱과 PC 홈페이지 동시 오픈, 일반 예매는 오전 7시대 개시(날짜별·노선별 순차). 확정 일정은 공식 공지 확인이 필요. [확인 S27의 대기번호 90만 번대 보도와 함께 사용]

게임 시사점: 3분 제한 + 강제 로그아웃 + 빨간 잔여 시간 + "접속대기인원 수" + 하단 [새로고침] 버튼(눌러도 되는 새로고침 vs 누르면 안 되는 새로고침)이 기차표 스테이지의 **독자적 메카닉**이 된다.

## 4. LMS 과제 제출

[2차 S57] 제출 상태 표기는 LMS마다 다르지만 "제출완료/제출됨/완료/제출 상태"를 확인하라는 조언. **파일만 선택하고 제출 버튼을 안 누른 상태**, **"임시저장"**, **업로드 중 멈춤**은 제출 미완료일 수 있다. 파일명 규칙(과목명·과제명·학번·이름), 이전 버전·빈 파일·깨진 PDF 오제출, 마감 10분 전보다 최소 1시간 전 제출 권장.

게임 시사점: "임시저장 vs 제출" 함정, 파일 내용 확인 단계, 파일명 규칙은 [2차]이지만 현실 공감도가 높아 유지한다. 구체적 오류 문구(용량 초과 등)는 이번에 확보하지 못했다 [미확인] — 자체 문구로 작성.

## 5. 반영 지침 (현실성 우선순위)

1. **흐름·단계·버튼명·제한시간·상태 전이**를 최대한 사실에 맞춘다 (위 표).
2. 오류 문구는 **패턴(말투와 길이)**을 따르되 문자열은 자체 작성. 확인된 짧은 일반 문구("이미 선택된 좌석입니다", "수강신청 기간이 아닙니다!", "접속대기인원 수")는 **관용적 일반 표현**이라 그대로 쓰되, 브랜드 식별 요소(로고, 이름, 고유 색)는 쓰지 않는다.
3. 레이아웃은 [기억]/[2차] 수준이므로 사용자가 실화면을 보고 보정한다 (스킨 토큰으로 분리).
4. 모든 수치는 `content/` 데이터의 파라미터로 두어 사용자가 실제와 다르면 고칠 수 있게 한다.
