# 1차 프로토타입 범위 (1–2주)

상태: 초안 v0.1 · 목표: **"60초 한 판이 정말 웃기고, 같은 시드가 재현되고, 아이폰 사파리에서 돈다"**를 증명한다.

## 1. 검증할 가설

1. **재미**: 정각 클릭 + 방해 카드 해결이 60초 동안 재미있고, 실패가 웃겨서 한 판 더 하고 싶어진다.
2. **결정론**: 같은 시드 → 같은 카드 스케줄 → 같은 결과 (테스트로 증명).
3. **일반성**: 같은 엔진으로 두 번째 스테이지(수강신청)를 **엔진 코드 변경 최소**로 추가할 수 있다.
4. **공유**: 결과 한 줄 + 시드 코드가 친구에게 전달되고 같은 판을 해볼 수 있다.
5. **모바일**: 아이폰 사파리(PWA)에서 입력·키보드·스크롤이 크게 깨지지 않는다.

## 2. 범위 안 (In)

- 스택: Vite + React + TypeScript + Tailwind + Vitest, GitHub Actions → GitHub Pages
- **엔진**: 고정 틱 루프, 시드 PRNG와 스트림 분리, 디렉터(예산·슬롯·쿨다운), 순수 `step` 리듀서, 입력 로그·리플레이
- **스키마**: zod로 스테이지·카드·문구 검증, 금지어 검사 스크립트 (간단 버전)
- **스테이지 2개**: ① 티켓팅(수직 슬라이스 풀 구현) ② 수강신청 (일반성 검증용, 고유 카드 최소 5개)
- **튜토리얼 1개**: 쉬운 변형, 반드시 성공 (고정 스케줄)
- **공통 카드 8개 + 고유 카드 5개씩**
- **결과 화면 + 텍스트 공유 카드**(Web Share/클립보드)
- **로컬 저장**: 진행·설정·최근 기록
- **PWA 최소 구성**: 매니페스트와 서비스 워커(오프라인 실행 가능)
- 접근성 최소: 시간 연장 설정, 모션 감소, 44px 기본 히트 영역(+의도적 축소는 카드 한정)
- **반응형 PC+모바일** (결정 0001): 같은 엔진, 레이아웃 컴포넌트만 분기. 마우스·터치 모두 논리 행동으로 변환
- **현실성 명세 반영** (`spec/realism-spec.md`): 단계·버튼명·제한시간·상태 전이를 데이터 파라미터로 구현
- 데일리 시드는 제외, 시드 코드 입력/복사만
- 문서: 이 문서들의 업데이트 + `docs/assets-licenses.md`

## 3. 범위 밖 (Out)

- 스테이지 3~5 (과제·기차표·한정빵), 취켓팅 보너스 라운드(시간이 남으면)
- 이미지 공유 카드, 데일리 챌린지, 사운드 디자인(최소 효과음만)
- 서버·계정·랭킹·분석 도구·광고
- 정교한 아트(임시 그래픽: 단색 + 아이콘으로 시작)

## 4. 일정 (제안)

### 1주차: 엔진과 첫 스테이지

| 일 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 프로젝트 셋업, CI(Pages 배포), 린트 규칙(`Math.random`·`Date.now` 금지 in engine) | main 푸시 시 배포됨 |
| 1 | **모바일 스파이크**: iOS 사파리 키보드·오버스크롤·핀치·오디오 잠금·Web Share·PWA | 결과표를 `design/difficulty-results-touch.md` §4.3에 기록 |
| 2 | PRNG·해시·스트림, 스케줄러(디렉터) + 테스트 | 스냅샷·퍼징 테스트 통과 |
| 3 | `step` 리듀서, 미션 체인, 정각 판정, 카드 상태 머신 | 봇이 티켓팅 한 판을 끝낼 수 있음 |
| 4 | 솔버 봇(해결 가능성 검증), 리플레이 해시 테스트 | 1,000 시드 중 규칙 위반 0 |
| 5 | 티켓팅 UI(대기열·보안문자·좌석도·결제), 카드 8개 구현 | 손으로 한 판 플레이 가능 |

### 2주차: 일반성·공유·플레이테스트

| 일 | 작업 | 완료 기준 |
|---|---|---|
| 6 | 결과 화면, 칭호, 공유 텍스트, 시드 입력/공유 링크 | 같은 시드로 두 기기에서 같은 판 |
| 7 | 튜토리얼 고정 스케줄 + "안내대로 하면 성공" 테스트 | 테스트 통과 |
| 8–9 | 수강신청 스테이지 (엔진 변경을 최소로) | 엔진 변경량을 기록(일반성 지표) |
| 10 | 접근성·저장·PWA 마무리, 법·윤리 체크리스트 점검 | 체크리스트 전 항목 통과 |
| 11–12 | **플레이테스트 5~8명**(아이폰 사용자 포함), 수치 조정 | 아래 성공 기준 평가 |
| 13–14 | 버퍼·버그 수정·문서 업데이트 | |

## 5. 성공 기준

- **재현성**: 100개 시드 리플레이 해시 일치(자동 테스트).
- **공정성**: 모든 유효 시드에서 솔버 봇 성공(자동 테스트).
- **튜토리얼**: 신규 플레이어 5명 중 5명이 첫 판 성공.
- **웃음 지표**(정성): "한 판 더"를 누른 비율, 결과 화면에서 웃음·반응(관찰 기록). 목표는 플레이한 사람의 과반이 같은 스테이지를 2판 이상.
- **공유 의향**(정성): "친구에게 보내고 싶은가" 질문에서 과반이 예.
- **일반성**: 두 번째 스테이지 추가 시 엔진 코어 변경이 합리적 수준(스테이지별 UI 컴포넌트와 콘텐츠 중심).
- **모바일**: 아이폰 사파리에서 키보드 올라올 때 레이아웃 파손·스크롤 함정 문제가 치명적이지 않음.

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| iOS 사파리 제약(진동·오디오·오버스크롤)으로 재미 요소 일부 불가 | 1일차 스파이크로 조기 확인, 대체 연출(시각·소리)로 설계 |
| 결정론 깨짐(시간 의존·UI 타이밍) | 엔진에서 시간·난수 API 금지(린트), 리플레이 테스트 |
| 카드 해결 불가능 시드 | 솔버 봇 + 파생 시드 재시도 |
| 범위 팽창(아트·스테이지) | 임시 그래픽 고정, 스테이지 2개 이후 추가 금지 |
| 법적 이슈(실제 브랜드 닮음) | 체크리스트 게이트, 가상 이름 상표 검색(출시 전) |
| 웃음이 없음 | 1주차 말에 티켓팅 하나만으로 지인 3명에게 시험, 카피·연출을 먼저 조정 |

## 7. 착수 전 선행 작업 (사람이 직접)

1. 원작 「11:59」 직접 플레이(10분)하고 메모 → 방해 요소 참고와 차별화 확인
2. 한국어 패러디/연습 게임 존재 여부 직접 검색 (research §7.2)
3. 가상 브랜드명 상표·웹 검색
4. 아이폰 사파리 실기기 준비(테스트용)
