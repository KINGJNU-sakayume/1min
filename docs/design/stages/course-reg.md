# 스테이지: 수강신청 `course-reg` — 실제 화면 대조표

상태: v0.1 (M4). realism-spec §2와 §7. **소유자가 실제 학교 수강신청 화면을 보고 "실화면 확인" 칸을 채운다.** 레이아웃은 학교마다 달라 스킨(`content/themes/meadow.json`)으로 분리했다.

한 줄 컨셉: 장바구니에 담을 땐 다 내 과목 같았다.

## 1. 단계 ↔ 게임

| 실제 (근거) | 게임 step | 화면·문구 | 파라미터 | 실화면 확인 |
|---|---|---|---|---|
| 로그인 상태 확인 [확인 S22·S56] | `login` (confirm) | "로그인", 가상 학번 안내 | — | [ ] 정각 전 로그인 화면 |
| 수강희망과목(장바구니) 목록 → 신청 [확인 S59] | `cart` (courseCart) | 과목명·시간·학점·"담은 인원 / 정원", "신청" | `courseCart.courses[]` | [ ] 목록 열 구성, 버튼 위치 |
| 신청 결과 확정 지연 [확인 S55] | `cart` 안의 pending | "처리 중…" → 신청완료/정원 초과 | `pendingTicks` 8~36틱 | [ ] 결과 표시 방식(팝업 vs 목록 갱신) |
| 시간표 확인 [확인 S59] | `timetable` (confirm) | "신청 완료 N과목 · N학점" | — | [ ] 시간표 화면 구성 |

## 2. 상태 전이와 문구

| 상태 | 게임 문구 | 근거 |
|---|---|---|
| notPeriod | "수강신청 기간이 아닙니다!" (관용 표현) | [확인 S55·S56] |
| full | "정원이 초과되었습니다." | [확인 S18·S21] |
| blocked | "수강 자격 요건을 충족하지 않아 신청이 불가능합니다." (자체 작성) | [확인 S55 패턴] |
| overlap | "시간표가 중복되어 신청할 수 없습니다." | [확인 S59] |

## 3. 수치

| 실제 | 게임 | 근거 |
|---|---|---|
| 희망 인원 ≤ 정원이면 모두 신청 처리 | 담은 인원 ≤ 정원인 과목은 마감 없음 | [확인 S59] |
| 인기 과목은 순식간에 마감 | 마감 틱 = 정각 + 180틱 × 정원/담은 인원 (±20%) → 인기 교양 약 3초 | [추측] |
| 결과를 1시간 동안 모름 | 처리 중 0.4~1.8초, 지연 카드 시 +3~4초 | [확인 S55] 압축 |
| "기간이 아닙니다"가 5분간 | 지연 카드 시 정각 뒤 3초 | [확인 S56] 압축 |
| 1초 2회 초과 클릭 불가 | 광클 카드: 1초(20틱) 2회 초과 시 3초 잠금 | [확인 S22] |

## 4. 소유자 확인 목록 (실화면 필요)

1. 장바구니 목록의 열 구성(과목번호·분반·교수명 등 — 게임에는 가상 과목명만)
2. "신청" 버튼이 줄 오른쪽인지 왼쪽인지 (현재 오른쪽)
3. 신청 결과가 팝업으로 뜨는지 목록 상태만 바뀌는지 (현재: 실패는 팝업, 성공은 상태만)
4. 정원/신청 인원 표기 방식 (현재 "담은 인원 N / 정원 M")
