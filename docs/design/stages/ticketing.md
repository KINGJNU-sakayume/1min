# 스테이지: 티켓팅 `ticketing` — 실제 화면 대조표

상태: v0.1 (M2). realism-spec §7의 "실제 화면 대조표"다. **소유자가 실제 예매처 화면을 보고 "실화면" 칸과 차이를 채운다.** 차이는 스킨(`content/themes/raspberry.json`)이나 스테이지 JSON 값만 고쳐 반영한다.

한 줄 컨셉: 정각에 "예매하기"를 눌러도 끝이 아니다. 단계가 여섯 개 더 있다.

## 1. 단계 ↔ 게임

| 실제 단계 (근거) | 게임 step | 버튼/문구 (게임) | 파라미터 위치 | 실화면 확인 |
|---|---|---|---|---|
| 날짜/회차 → 예매하기 [2차 S54] | `open` | "예매하기", 오픈 전 "예매 오픈 전", 서버 시간 표시 | `director.json` `prerollTicks`, `judgment` | [ ] 오픈 전 버튼 모양·문구 |
| 대기열 [확인 S4·S6·S10, 2차 S48] | `queue` | "현재 내 앞에 N명이 계신 것으로 추정됩니다", 새로고침 | `queue.*` (stage JSON) | [ ] 대기 화면 문구 위치(스킨 `queueNoticePosition`), 진행 막대 유무 |
| 안심예매 문자 입력 [2차 S54] | `captcha` | "입력완료" | `input.length` 5~6, `regenerateOnWrong` | [ ] 글자 수, 새로고침 버튼 유무 |
| 좌석 선택 [2차 S48·S54] | `seat` | 1층/2층 탭, 구역 목록, "좌석선택완료", "이미 선택된 좌석입니다." | `seatMap.*`, 스킨 `pcMainRatio`·`seatShape` | [ ] 좌석도:패널 비율, 구역 목록 위치 |
| 가격/할인 [2차 S54] | `price` | 기본가 0매 → 1매, "다음 단계" | `quantity.initial` 0, `skippableAtLevel` 2 | [ ] 0매 시작 여부 |
| 주문자 확인 [2차 S54] | `buyer` | 생년월일 6자리, "다음 단계" | `input.length` 6, `skippableAtLevel` 2 | [ ] 입력 위치 |
| 결제 [2차 S48·S54·S58] | `pay` | 결제수단, 취소수수료·취소기한 동의, "결제하기", 남은 시간 | `timeLimitTicks` 400(20초), `displayScale` 15(→ "05:00") | [ ] 타이머 표시 위치·형식 |

## 2. 수치

| 실제 | 게임 | 근거 |
|---|---|---|
| 좌석 점유 후 약 5분 | 결제 20초(400틱)를 "05:00"처럼 표시 | [2차 S58] |
| 대기 인원 수천~수만 | 판정별 시작 인원 120 ~ 18,000, 대기 8~28초 | [추측] 연출 |
| 새로고침 시 맨 뒤로 | 12,000명, 약 25초 | [2차 S48] |
| 좌석 매진 속도 | 시작 시 60~80% 매진, 0.3~1.4초마다 1~2석씩 | [추측] |
| 화면 반영 지연 | 8틱(0.4초) 늦게 회색 | [추측] → "이미 선택된 좌석입니다" |
