# 가상 브랜드와 화면 톤 가이드: 닮되 베끼지 않는 선

상태: 초안 v0.1. 법률 자문이 아니다. 상업 출시 전 전문가 검토를 권한다.

## 1. 원칙

1. **구조는 빌려도 표면은 새로 만든다.** "대기열 → 좌석 → 결제" 같은 일반적 흐름은 누구나 쓰는 패턴이다. 로고·고유 색·고유 아이콘·고유 문구·실제 인물명은 쓰지 않는다.
2. **패러디임이 한눈에 보이게 한다.** 한국에서는 패러디 의도가 분명하지 않으면 침해로 판단된 사례가 소개된다 (→ research §9, S41). 웃음 장치가 분명해야 한다.
3. **실제 서비스로 오인되면 안 된다.** 로그인·결제처럼 보이는 입력은 가짜만 받고, 실제 개인정보·비밀번호를 요구하는 UI를 만들지 않는다.
4. **비하하지 않는다.** 웃음의 대상은 시스템과 상황이다. 특정 학교·사람·팬덤을 조롱하지 않는다.

## 3. 시각 톤

### 3.1 "닮은 느낌"을 만드는 일반 패턴 (OK)

- 줄어드는 대기 숫자, 진행 막대, 단계 표시줄
- 좌석 배치도(격자·반원형) — 단, 좌석 아이콘은 실제 사이트 고유 모양 대신 **젤리빈 모양(타원)**처럼 우리 것을 쓴다.
- 모달 팝업, 오류 코드, 타이머, 약관 체크박스
- 관공서·플랫폼 특유의 건조한 공손체

### 3.2 베끼지 않는 선 (하지 않는 것)

| 하지 않음 | 이유 |
|---|---|
| 실제 로고·워드마크·마스코트 | 상표 |
| 특정 서비스를 연상시키는 고유 색 조합(브랜드 컬러 + 보조색 세트) | 식별력. 가상 브랜드는 **각자 다른 자체 팔레트** |
| 실제 공지·약관·오류 문구 복사 | 저작·혼동. 문구는 직접 쓴다 |
| 같은 레이아웃 비율·아이콘 세트 그대로 | 트레이드 드레스성 위험 [추측] |
| 실제 사진·아티스트 이미지·교수 얼굴 | 초상·저작 |
| 실제 사건명·피해자·실명 | 명예·윤리 |

### 3.3 가상 브랜드별 팔레트 가이드 (예시)

디자인 토큰은 Tailwind 테마 변수로 정의한다. 스테이지 `theme` 필드에서 참조한다 (→ `spec/stage-format.md`).

| 브랜드 | 분위기 | 팔레트 방향 |
|---|---|---|
| 딱표 | 화려하지만 허술 | 라즈베리 + 크림 + 짙은 남색, 둥근 모서리 |
| 수강쇼핑 | 관공서풍 쇼핑몰 | 풀빛 + 회색 + 연노랑, 각진 표 |
| 이러닝쿨 | 학내 시스템 | 청회색 + 흰색, 촘촘한 목록 |
| 번개레일 | 공공 교통 | 하늘색 + 주황 포인트 |
| 도깨비빵 | 편의점 + 만화 | 형광 연두 + 보라, 손글씨체 안내문 |

색은 접근성 기준(텍스트 대비 4.5:1 이상)을 우선한다.

### 3.4 타이포·모션

- 한글 폰트는 라이선스가 명확한 것(예: 오픈 라이선스 폰트)을 선택하고 사용 전 라이선스를 문서에 기록한다. [미확인: 폰트 선정 전]
- 모션 감소 설정(`prefers-reduced-motion`)을 존중하고, 깜박임은 초당 3회를 넘지 않는다.

## 4. 마이크로카피 톤

원칙: **건조한 시스템 말투 + 상황의 부조리**. 시스템은 끝까지 공손하고, 플레이어만 절박하다.

### 4.1 시스템 문구 샘플 (전부 자체 창작, 실제 문구 아님)

- 대기열: "현재 내 앞에 **14,937명**이 계신 것으로 추정됩니다. 추정이라 틀릴 수 있습니다."
- 새로고침 유혹: "새로고침하시면 처음부터 다시 줄을 서실 수 있습니다. (저희도 속상합니다)"
- 좌석 경합: "앗, 한발 늦으셨어요. 그 자리는 방금 다른 분의 소중한 자리가 되었습니다."
- 광클 제한: "너무 빠른 손가락이 감지되었습니다. 3초간 숨을 고르세요."
- 서버 지연: "서버가 열심히 생각 중입니다. 서버도 우리와 같은 마음입니다."
- 모바일 안내(수강쇼핑): "원활한 이용을 위해 PC 사용을 권장합니다. (지금 PC가 없으시다면 저희도 방법이 없습니다)"
- 보안문자: "사람임을 증명해 주세요. 방금 전의 당신을 포함해서."
- 팝업 차단: "팝업이 차단되었습니다. 중요한 팝업이니 허용해 주세요. 중요하지 않은 팝업은 이미 4개 떠 있습니다."
- 과제: "임시저장되었습니다. (제출 완료가 아닙니다. 아니, 제출이 아닌 겁니다.)"
- 기차: "예매 화면으로 이동 중입니다…… 이동 중입니다…… 이동 중입니다."
- 오류 코드 형식: `ERR-1004 (ㅠㅠ)` 같이 가상 코드를 쓴다.

### 4.2 말투 규칙

- 시스템/공지 = 존댓말, 짧고 건조하게. 플레이어를 부르는 호칭은 "고객님" 또는 호칭 생략
- 결과·공유 문구 = 반말·구어체 허용 (→ `design/difficulty-results-touch.md`)
- 비속어 금지(기본). 은어는 널리 쓰이는 것만(피켓팅, 취켓팅, 광클, 올클)
- 실패를 놀리되 사람을 깎아내리지 않기: "당신 탓이 아닙니다. 대기번호 90만 번대의 탓입니다."

## 5. 법·윤리 체크리스트 (출시 게이트)

각 스테이지 병합 전 아래를 확인한다.

- [ ] 실제 브랜드·학교·인물·단체명이 화면·코드·에셋·커밋 메시지·SEO 메타에 없는가
- [ ] 로고·색·아이콘·레이아웃이 특정 실제 서비스를 연상시킬 만큼 유사하지 않은가
- [ ] 문구가 실제 공지를 복사하지 않았는가
- [ ] 입력 UI가 실제 개인정보·비밀번호를 요구하지 않는가 (가짜 값만)
- [ ] 첫 화면 또는 푸터에 "패러디이며 실제 서비스와 무관" 고지가 있는가
- [ ] 매크로·우회·부정 구매를 가르치는 내용이 없는가 (풍자는 OK)
- [ ] 사건·피해자를 소재로 삼지 않았는가
- [ ] 에셋(폰트·소리·이미지) 라이선스를 문서에 기록했는가
- [ ] 수익화를 하게 되면: 상업적 패러디에 더 엄격하다는 점을 고려해 재검토했는가 (→ 질문 4)

## 6. 호스팅·도메인 메모 [추측]

GitHub Pages 도메인에 실제 서비스를 닮은 단어(예: 실제 예매처 이름)가 들어가면 사칭으로 읽힐 수 있다. 저장소·도메인 이름에 실제 브랜드명을 쓰지 않는다.
