# 난이도 곡선 · 결과 화면 · 공유 카드 · 터치 재미

상태: 초안 v0.1. 수치는 모두 시작값이며 플레이테스트로 조정한다.

## 1. 난이도 곡선

### 1.1 설계 목표 (참고 근거: research §8)

- 마이크로게임 계열의 기준: 규칙이 직관적이어서 두세 번째 시도에 깰 수 있을 것 [확인 S37]
- 좌절은 필요하지만 불공정해 보이면 플레이어를 빨리 잃는다 [확인 S39]
- 따라서: **첫 판은 반드시 성공 → 두세 판 안에 첫 실패 → 실패가 웃겨서 한 판 더**

### 1.2 레벨 구조

| 단계 | 이름 | 목적 | 카드 비용 예산 | 슬롯 | 보장 |
|---|---|---|---:|---:|---|
| 0 | 튜토리얼 | 규칙 학습, 성공 경험 | 3 | 1 | 고정 스케줄, 안내대로 하면 100% 성공 |
| 1 | 워밍업 | 1~2개 카드 | 6 | 1 | 성공률 목표 80% |
| 2 | 보통 | 카드 종류 확대 | 10 | 1 | 성공률 목표 55% |
| 3 | 지옥 | 시너지 등장 | 14 | 2 | 목표 35% |
| 4 | 피켓팅 | 리셋 카드 등장 | 18 | 2 | 목표 20% |
| 5 | 서버 폭주 | 동시 3슬롯, 가짜 경고 | 22 | 3 | 목표 10% |

성공률 목표는 **솔버 봇**이 아니라 사람 플레이테스트 기준이다. 봇은 "해결 가능성"만 보장한다 (hazard-system §5-6).

### 1.3 한 판 안의 곡선 (60초)

램프: `0–10초` 정각 클릭과 첫 카드 / `10–35초` 카드 점증 / `35–50초` 피크 / `50–60초` 마지막 결제 압박 + 반전(희망 → 절망 또는 성공). 구간별 예산 가중치 예: 10%·30%·40%·20%.

### 1.4 스테이지 간 해금

튜토리얼(과제 쉬운 변형, 성공 필수) → A 티켓팅 → B 수강신청 → D 기차표 → E 한정빵 → C 과제 풀버전. 잠금은 "이전 스테이지를 1회 시도"로만 풀어 진입 장벽을 낮춘다. 성공 요구 해금은 두지 않는다.

### 1.5 재시도 규칙

- 실패 직후 "한 번 더" 버튼을 가장 크게. 같은 시드 재도전은 결과 화면에서 가능 ("복수전")
- 새 판은 새 시드. 같은 시드를 반복해서 외워 이기는 것은 허용 (학습 쾌감)

## 2. 결과 화면

### 2.1 결과 유형 (예: 티켓팅)

| 코드 | 조건 | 칭호(자체 창작) |
|---|---|---|
| success-perfect | 성공 + 남은 시간 > 15초 | "광클 장인" |
| success-close | 성공 + 남은 시간 < 3초 | "결제 3초 전의 기적" |
| fail-sniped | 좌석 경합에서 연속 실패 | "한발 늦은 사람" |
| fail-queue | 대기열 도중 새로고침 | "새로고침의 손" |
| fail-captcha | 보안문자 3회 오입력 | "인간 증명 실패" |
| fail-timeout | 결제 시간 만료 | "결제창 앞의 철학자" |
| fail-lock | 광클 제한 | "손가락이 너무 빨랐던 사람" |
| fail-fatal | 치명 카드 | "서버와 함께 떠난 사람" |
| bonus-win | 취켓팅 보너스 성공 | "취소표의 신" |

스테이지마다 칭호 세트를 가진다 (콘텐츠 JSON의 `results`). 칭호는 반드시 **원인이 한 줄로 보이게** 한다.

### 2.2 화면 구성

1. 큰 칭호 + 한 줄 원인("결제 버튼까지 0.4초 모자랐습니다")
2. 타임라인 막대: 60초에 카드가 언제 켜졌고 어디서 막혔는지 (이모지 그리드와 같은 데이터)
3. 조합 이름(시너지) 표시
4. 버튼: 한 번 더 / 같은 판 복수전 / 공유 / 다음 스테이지

### 2.3 취켓팅 보너스 라운드

실패 후 10초짜리 보너스: 취소표가 랜덤 위치에서 반짝이는 것을 탭. 시드 기반이며 성공 확률은 아주 낮게(원하는 만큼 웃기게). 근거: 기차표 명절 승차권의 약 41%가 취소·반환됐다는 보도와 취켓팅 문화 [확인 S28, S8, S9].

## 3. 공유 카드

### 3.1 형식

- **텍스트 공유**(필수): 스포일러 없는 한 줄 + 이모지 타임라인 + 시드 코드. Web Share API가 있으면 사용하고 없으면 클립보드 복사. [아이폰 사파리 동작은 프로토타입에서 확인 필요]
- **이미지 공유**(선택, 후순위): 캔버스로 결과 카드를 그려 이미지로 저장. 이미지 저장 동작은 프로토타입에서 확인 필요.
- Wordle 교훈: 결과를 그리드로 보여주되 정답(해결법)은 숨긴다. 같은 퍼즐을 같이 하는 커뮤니티성이 강하다 [확인 S40]. 같은 시드를 친구와 공유 가능하게 한다.

### 3.2 텍스트 카드 예시

```
1분 전 🎟️ 딱표 #K7M2Q
결제 3초 전의 기적 ⏱️ 0.4초 남기고 성공
🟩🟩🟨🟥🟨🟩🟩🟩  (카드 8개 중 해결 5)
#1분전 #피켓팅
```

이모지 의미: 🟩 해결, 🟨 늦게 해결, 🟥 실패. 카드 내용은 노출하지 않는다.

### 3.3 공유 문구 후보 (스테이지별 칭호 아래 한 줄)

티켓팅
- "친구한테 '내가 잡아줄게' 하고 대기번호 14,937번 받음"
- "좌석을 눌렀는데 내 자리가 이미 다른 사람 자리였다"
- "손은 빨랐는데 서버가 더 빨랐다"

수강신청
- "장바구니 만석, 현실은 정원 마감"
- "보안문자는 맞췄는데 인생은 못 맞췄다"
- "'PC로 접속하세요'를 폰으로 보다가 졸업이 멀어졌다"

과제 업로드
- "임시저장을 제출로 믿은 죄"
- "11:59:58, 파일명이 틀렸습니다"
- "업로드 막대는 99%에서 평생 산다"

기차표
- "대기번호 90만. 설날에는 못 갈 수도"
- "엄마가 전화로 '잡았니?'라고 묻는 순간 결제 시간이 끝났다"

한정빵
- "트럭을 따라갔지만 트럭은 나를 따라오지 않았다"
- "스티커는 중복이었고 빵은 식어 있었다"

문구는 모두 자체 창작이다. 공유 직전에 **발견 즐거움**을 위해 랜덤 선택(시드와 독립된 `copy` 스트림).

## 4. 터치에서 오는 재미

### 4.1 재미 소재 (우선순위 순)

| 소재 | 감각 | 대응 카드 | 구현 메모 |
|---|---|---|---|
| 작은 버튼 | "분명히 눌렀는데" | 모든 스테이지 | 히트 영역은 44px 이상을 기본으로 하고, **일부 카드만** 의도적으로 줄인다 (접근성 설정으로 끌 수 있게) |
| 키보드 가림 | 보안문자 입력창이 올라와 버튼을 덮음 | captcha | iOS 사파리 `visualViewport` 처리와 입력 포커스 동작 검증 필요 [미확인] |
| 스크롤 함정 | 스크롤하다가 버튼 위치가 이동 | 수강쇼핑 목록 | `overflow` 스크롤 컨테이너와 페이지 스크롤 충돌 확인 필요 |
| 당겨서 새로고침 | 실제 새로고침 공포를 터치로 재현 | refresh-temptation | iOS 사파리 오버스크롤 제어(`overscroll-behavior`) 지원 범위 확인 필요 [미확인] |
| 핀치 줌 | 좌석도에서 확대하다 다른 구역이 눌림 | ticketing | 멀티터치 처리와 브라우저 줌 충돌 확인 필요 |
| 길게 누르기 | 업로드 진행 가속(원작의 로딩바 클릭 아이디어 변주) | 이러닝쿨 | |
| 스와이프 | 편의점 지도 이동 | 도깨비빵 | |
| 진동 | 실패 순간의 촉감 | 모든 결과 | iOS 사파리에서 진동 API 지원 여부 확인 필요 [미확인, 지원되지 않을 가능성] |
| 사운드 | 알림음, 실패음 | | 모바일 브라우저는 사용자 입력 후에만 오디오 재생을 허용하는 경우가 많다 [추측] |

### 4.2 접근성·안전 기본값

- 시간 연장 모드(60초 → 90초), 작은 버튼 모드 해제, 모션 감소, 색 대비 모드
- 광과민 보호: 빠른 점멸 금지
- 접근성 모드는 공유 카드에 표시하지 않는다 (차별 없이 같은 시드로 비교 가능, 단 `assist` 플래그를 로컬에만 저장)

### 4.3 모바일 특화 확인 항목 (프로토타입 스파이크)

아이폰 사파리/PWA에서 확인할 것: ①키보드 올라올 때 레이아웃(`visualViewport`) ②오버스크롤·당겨서 새로고침 ③핀치 줌 억제 ④오디오 잠금 해제 ⑤Web Share API ⑥홈 화면 추가 후 전체 화면 동작 ⑦localStorage 용량과 삭제 정책. 전부 [미확인]이며 프로토타입 1주차 초반에 스파이크로 해결한다.

#### 스파이크 결과 (M0, 2026-10-16)

도구: `spike.html`(배포 경로 `/1min/spike.html`) + Playwright `e2e/mobile-spike.spec.ts`. 이 개발 환경에는 **Chromium만** 있어 iPhone 13 뷰포트·터치를 Chromium으로 에뮬레이션했다. CI에는 Linux WebKit 잡(`spike-webkit`, 참고용)이 있다. **둘 다 실제 iOS 사파리가 아니므로 모든 항목은 실기기 확인 전까지 확정이 아니다.**

| # | 항목 | 앱의 대응(구현) | Chromium iPhone 에뮬레이션 | 판정 |
|---|---|---|---|---|
| ① | 키보드 올라올 때 레이아웃 | `visualViewport` resize/scroll로 하단 확인 버튼을 키보드 위로 이동 | API 있음. 에뮬레이션에선 키보드가 안 떠서 가림 0px | **실기기 확인 필요**: 보안문자 입력 시 "입력완료" 버튼이 키보드 위에 보이는가 |
| ② | 오버스크롤·당겨서 새로고침 | `body { overscroll-behavior: none }` | 지원 true | **실기기 확인 필요**: 맨 위에서 당겼을 때 새로고침/바운스가 일어나는가 (iOS 16+ 지원으로 [기억]) |
| ③ | 핀치·더블탭 줌 억제 | `touch-action: manipulation` + `gesturestart` preventDefault. 뷰포트 `user-scalable=no`는 접근성 때문에 쓰지 않음 | 지원 true | **실기기 확인 필요**: 좌석도에서 두 손가락 확대 시 페이지 전체가 확대되는가 |
| ④ | 오디오 잠금 해제 | 첫 사용자 탭에서 `AudioContext.resume()` + 짧은 비프 | `running` | **실기기 확인 필요**: 무음 스위치 상태에서 소리가 나는가, 첫 탭 전에는 안 나는가 |
| ⑤ | Web Share / 클립보드 | `navigator.share` → `clipboard.writeText` → `execCommand('copy')` 폴백 | share 없음 → clipboard 성공 | **실기기 확인 필요**: 공유 시트가 뜨는가, 닫으면 복사로 넘어가는가 |
| ⑥ | 홈 화면 추가 후 전체 화면 | 매니페스트(standalone, scope `/1min/`), apple-touch-icon, 서비스 워커 사전 캐시 | 오프라인 실행 e2e 통과 | **실기기 확인 필요**: `plan/release-checklist.md` §2 |
| ⑦ | localStorage | 512KB 쓰기·삭제, 모든 접근 try/catch | 성공 | **실기기 확인 필요**: 프라이빗 모드에서 앱이 정상 동작하는가. 7일 미사용 시 삭제 정책(ITP)은 [기억] |
| 참고 | 진동 `navigator.vibrate` | 있으면 사용, 없으면 시각 연출 | true(Chromium) | iOS 사파리는 미지원으로 [기억] → 시각 연출을 기본으로 설계 |

실기기 확인 방법: 배포 후 아이폰 사파리에서 `https://<사용자>.github.io/1min/spike.html`을 열고 표의 ✅/❌와 버튼 동작을 확인해 이 표의 "판정" 칸을 갱신한다.
