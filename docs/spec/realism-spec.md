# 현실성 명세 (Realism Spec)

상태: 초안 v0.1 · 정본 · 근거: `research/realism-findings.md`(이하 RF), `research/pain-points-and-references.md`(이하 PP)

목표: 플레이어가 **"아 이 화면 그거다"**라고 느끼게 한다. 현실성은 아래 순서로 투자한다.

1. **흐름**: 단계 순서와 각 단계에서 막히는 방식
2. **라벨**: 버튼 이름, 안내 문구의 말투와 길이
3. **타이밍**: 제한시간, 대기 속도, 지연
4. **상태 전이**: 로딩 → 결과 불명 → 뒤늦은 실패 같은 심리적 리듬
5. **레이아웃**: 화면 구성 (근거가 약하므로 스킨 토큰으로 분리)

범위 밖: 실제 서비스의 로고, 이름, 고유 색 조합, 실제 사진. 이 저장소는 공개 레포이고 GitHub Pages로 배포되므로 **브랜드 식별 요소는 가상**으로 둔다. (결정 기록 `decisions/0001-owner-answers.md`) 현실성은 위 1~4번에서 최대화한다.

## 0. 공통 원칙

- 모든 수치(제한시간, 대기 속도 등)는 스테이지 JSON 파라미터. 코드에 하드코딩 금지. 실제와 다르면 값만 고친다.
- 문구는 `content/copy/ko.json`의 키. 브랜드 이름·로고 텍스트도 이 파일 한 곳에서만 정의한다.
- 일반 관용 표현("이미 선택된 좌석입니다", "수강신청 기간이 아닙니다!", "접속대기인원 수")은 그대로 사용 가능. 긴 공지문 복사는 금지.
- 시스템은 **끝까지 사무적**이다. 코미디는 플레이어의 절박함과의 대비에서 나온다.
- 화면은 **PC와 모바일 모두 지원**한다 (결정 기록). PC에서는 "브라우저 안의 창" 느낌(팝업 창, 좌측 좌석도 + 우측 패널), 모바일에서는 전체 화면 단계 전환으로 같은 로직을 다르게 배치한다. 엔진은 동일하다.

## 1. 티켓팅 스테이지 `ticketing`

근거: RF §1, PP §3

### 1.1 화면 시퀀스 (미션 체인)

| step id | 화면 | 버튼/문구 | 파라미터 |
|---|---|---|---|
| `open` | 공연 상세 + 카운트다운 | **"예매하기"** (정각에 활성) | 오픈 판정 §5 (game-rules) |
| `queue` | 대기 화면 | "내 앞에 N명" / 안내문 / 새로고침 유혹 | `queue.base`, 줄어드는 속도 가변 |
| `captcha` | 안심예매 문자 입력 | **"입력완료"** | 길이 5~6, 오입력 시 새 이미지 |
| `seat` | 좌석 선택 (구역 목록 + 좌석도 + 선택 패널) | **"좌석선택완료"** | 구역 N개, 1층/2층 탭 |
| `price` | 가격/할인 | **"다음 단계"** | **기본가 수량이 0매로 시작** |
| `buyer` | 주문자 확인 | **"다음 단계"** | 생년월일 6자리 입력 |
| `pay` | 결제 | 약관 동의 → **"결제하기"** | `timeLimitTicks`, 무통장 선택지 함정 |

시간 압축: 60초에 맞추려고 `price`와 `buyer`는 **난이도 1~2에서는 자동 통과** 옵션(`skippableAtLevel`)을 둔다. 난이도 3 이상에서 모두 등장.

### 1.2 대기열 동작

- 숫자는 판정(PERFECT~SLOW)로 시작값이 정해지고 매 틱 결정적으로 감소한다. 감소 속도는 **일정하지 않음**: 구간별로 빨라졌다 멈춘다 (시드의 `queue` 스트림).
- 새로고침 버튼 탭 또는 모바일 당겨서 새로고침: **순번 초기화** (RF §1, S48). 뒤로가기 시도도 같다.
- 한 계정 한 대기열: "다른 기기로도 줄 서기" 유혹 UI를 누르면 기존 대기열 종료 (PP S4).
- 대기 중에는 **다른 카드(카톡 알림 등)가 떠도 대기 화면을 벗어나면 안 됨**: 카드 해결이 오버레이 안에서 이뤄지게 설계.

### 1.3 좌석 경쟁

- 좌석도의 각 좌석은 상태: 선택가능 / 선택불가 / 내가 선택. 선택 불가 좌석이 시간이 지나며 **시드로 정해진 틱에 늘어난다** (경쟁자 모델).
- 선택 순간 이미 가져간 경우: **"이미 선택된 좌석입니다"** 팝업 (RF §1, S48). 확인 닫기 후 재선택.
- 좌석 선점 후 결제 제한: 기본 **5분 개념을 20초로 압축**해 표시 (가상 시간 표기 "04:59"가 빠르게 감소하는 연출도 가능). 압축 비율은 파라미터.
- 취켓팅 보너스: 인터파크식 **예매대기** (매진 좌석에 대기 걸기 → 문자 알림 → 6시간 내 결제)는 게임에서 "알림이 오면 10초 내 결제" 형태로 변형 (RF §1, S49: 2016년 자료이므로 실제 정책 재현이 아니라 오마주).

### 1.4 고유 카드 (데이터로 정의, ≥5)

`refresh-temptation`, `seat-snipe`, `one-account-one-queue`, `zone-click-limit`, `price-zero-qty`(수량 0매 함정), `buyer-birth-typo`(생년월일 6자리), `bank-transfer-trap`(무통장 선택 시 좌석이 풀림 연출), `family-ping`(카톡)

## 2. 수강신청 스테이지 `course-reg`

근거: RF §2, PP §4

### 2.1 화면 시퀀스

| step id | 화면 | 버튼/문구 | 비고 |
|---|---|---|---|
| `login` | 로그인 상태 확인 | — | 정각 직전 자동 로그아웃 카드 가능 |
| `cart` | 담아둔 과목(장바구니/수강희망과목) 목록 | **"신청"** (정각에 활성) | 과목 N개, 우선순위 순 |
| `submit` | 신청 결과 | 확인 팝업 | **결과가 늦게 확정됨** |
| `timetable` | 시간표 확인 | — | 겹침 경고 |

### 2.2 신청 결과 모델 (현실성의 핵심)

과목마다 시드로 `잔여석`과 `마감 틱`이 정해진다. 신청 버튼을 누르면 상태가 이렇게 전이한다.

`idle → pending("처리 중입니다…", 서버 지연 D틱) → success | full("정원이 초과되었습니다") | blocked(자격 오류) | notPeriod("수강신청 기간이 아닙니다!")`

- **"수강신청 기간이 아닙니다!"** 팝업 (RF §2, S56): 정각 직전에 누르면 뜨고, 정각 이후에도 **서버 지연 카드가 겹치면 수 초간 계속** 뜰 수 있다.
- **무한 로딩 → 뒤늦은 실패**: `pending`이 길게 이어진 뒤 `full`로 확정 (S55). 이때 플레이어는 이미 다음 과목을 눌렀을 수 있다.
- **담기는 되는데 신청에서 자격 오류**: 사유 문구가 사무적인 팝업 (S55의 "…수강이 불가능합니다" 패턴. 문구는 자체 작성).
- **대기 순번 표시 오류**: 정원 마감 과목의 대기 순번이 줄지 않고 **늘어난다** (S56).
- 광클 제한: 짧은 시간에 신청 버튼 연타 시 잠금 (S22: 1초 2회 초과 불가 매뉴얼).
- 시간표 중복 시 신청 불가 (S59).
- 로그인이 10분 걸리는 현상은 `login` 스텝의 지연 카드로 표현 (S56).

### 2.3 고유 카드 (≥5)

`not-period-popup`, `infinite-loading`, `late-full`, `cart-ok-submit-blocked`, `queue-number-bug`, `click-limit`, `timetable-overlap`, `auto-logout`, `mobile-not-supported-notice`

## 3. 명절 기차표 스테이지 `train`

근거: RF §3, PP §5

### 3.1 화면 시퀀스

| step id | 화면 | 버튼/문구 | 비고 |
|---|---|---|---|
| `open` | 안내 + 카운트다운 | 입장 버튼 | 정각 판정 |
| `wait` | 접속 대기 | **"접속대기인원 수"** + 진행 표시 | 이탈 시 맨 뒤로 |
| `login` | 로그인 | 회원번호/비밀번호 입력 | **로그인 이후 3분 카운트 시작** (스테이지 내에서는 압축) |
| `search` | 조건 선택 | **"명절승차권 예약"** | 구간/날짜/여객 수. **돌아오는 편 날짜 함정** |
| `pick` | 열차 선택 | 예약 | 잔여석 조회 방식 vs 시간대 바로 예약 |
| `pay` | 결제 | 결제 | 미결제 시 자동 취소 |

### 3.2 규칙

- **제한시간 카운트다운은 빨간색**, 예약요청 횟수와 함께 표시 (S52). 시간이 다 되면 **강제 로그아웃** → `login` 단계로 되돌림 (resetStep).
- 대기 화면에서 벗어나면 순번이 맨 뒤로 (S51). 단, **하단의 [새로고침] 버튼은 허용**되는 새로고침이라는 함정: 브라우저 새로고침 유혹(금지)과 화면 내 새로고침(허용)을 구분해야 한다.
- 매수 제한: 1회 6매, 왕복 12매 (S52, 현행 [미확인]). 수량을 초과해 선택하면 거부.
- 로그인 비밀번호 규칙 함정: 4자리 숫자 비밀번호(역 발매기용)는 거부 (S52).
- 결제 기한: 코레일톡 승차권 결제는 10분, 출발 임박 시 5분 (S50, 2022 기준). 게임에서는 압축.
- 대기번호는 **90만 번대**까지 올라갈 수 있게 한다 (S27 보도). 난이도 5에서 표시.

### 3.3 고유 카드 (≥5)

`queue-leave-penalty`, `forced-logout-3min`, `return-date-trap`, `password-rule-reject`, `seat-sold-out-cancel-round`, `parents-call`, `in-app-browser-warning`

## 4. 과제 업로드 스테이지 `homework` (마감형, 레인 병렬)

근거: RF §4, 11:59 요약 (PP §2)

- 레인(과제) 3~5개. 각 레인: `prepare → convert → upload → confirm`.
- 상태 문구는 제출 상태 확인 함정을 반영: **"임시저장"은 제출이 아니다** (S57). `confirm` 단계에서 상태 표시를 보지 않고 넘어가면 실패 (최종 판정에서 "제출 상태: 임시저장" 노출).
- 파일 선택만 하고 제출 버튼 미클릭, 업로드 멈춤, 파일명 규칙 위반, 용량 초과, 깨진 PDF 같은 함정 카드는 [2차/추측]이므로 문구는 자체 작성한다.
- 창이 쌓이는 연출은 원작 아이디어에서 영감을 받되 구현·연출·문구는 독자 설계.

## 5. 한정빵 오픈런 스테이지 `convenience-bread` (공간형)

근거: PP §6.1

- 지도(편의점 3곳)를 이동하며 입고 시각(밤 10시대)에 맞춰 재고를 확보. 점포당 입고량 소수, 앞사람이 먼저 집어감, 손글씨 품절 안내문, 번호표와 1인 한도.
- 구현은 2차 이후. 프로토타입 범위 밖.

## 6. 스킨(레이아웃) 분리

레이아웃 정보는 근거가 약하므로 **스킨 토큰**으로 분리한다.

- `theme` 필드 → Tailwind CSS 변수 세트(`--c-primary` 등)와 컴포넌트 변형(`seatShape`, `headerStyle`, `popupStyle`)
- 사용자가 실제 화면을 보고 "좌석도 비율", "대기 화면 문구 위치", "팝업 모양"을 알려 주면 **스킨 값만 수정**해 반영한다. 로직 변경 없음.
- 브랜드 이름·로고 텍스트는 `copy/ko.json`의 `brand.*` 키 한 곳.

## 7. 현실성 검증 방법

1. 스테이지마다 `docs/design/stages/{id}.md`에 **"실제 화면 대조표"**를 둔다: 실제 단계 ↔ 게임 단계, 실제 문구 패턴 ↔ 게임 문구, 수치 ↔ 파라미터.
2. 사용자(개발자)가 실제 예매처·학교 화면을 열어 확인한 뒤 차이를 `decisions/`나 스킨 값으로 기록한다.
3. 근거 라벨을 유지한다: 확인/2차/기억/미확인.
