# 게임 규칙 (핵심 문서 1/2)

상태: 초안 v0.1 · 정본. 구현은 이 문서를 따르고, 바뀌면 이 문서를 먼저 고친다.
관련: `spec/stage-format.md`(스테이지 데이터), `design/hazard-system.md`(카드·시드), `design/difficulty-results-touch.md`(곡선·결과)

## 1. 한 줄 요약

> **60초 안에, 쏟아지는 방해를 해결하며, 미션 체인을 끝까지 완료하라.** 성공해도 웃기고 실패해도 웃기다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 판(Run) | 한 스테이지의 한 번의 플레이. 길이 60초 (+ 정각 맞추기 프리롤). |
| 스테이지(Stage) | 소재 단위 콘텐츠 (티켓팅, 수강신청, …). JSON으로 정의. |
| 미션 체인(Mission Chain) | 스테이지가 요구하는 순서 있는 단계들. 마지막 단계 완료 = 성공. |
| 모드(Mode) | `open`(정각 오픈형) 또는 `deadline`(마감형). |
| 정각(T0) | open 모드에서 오픈 시각. 오픈 전 클릭은 감점. |
| 카드(Card) | 방해 하나 (→ hazard-system). |
| 시드(Seed) | 판의 모든 무작위를 결정하는 값. 같은 시드 = 같은 판. |
| 틱(Tick) | 논리 시간 단위 50ms. 60초 = 1,200틱. |

## 3. 판의 흐름 (상태 머신)

```
READY → PREROLL(≤5s) → RUNNING(60s) → RESULT
                           ↘ BONUS(10s, 선택) ↗
```

1. **READY**: 스테이지·난이도·시드 확인, 시작 버튼.
2. **PREROLL** (open 모드만): 서버 시계가 T0까지 카운트다운(최대 5초). 플레이어는 **정각에 맞춰 "오픈" 버튼을 누른다** (§5). deadline 모드는 프리롤 없이 바로 RUNNING.
3. **RUNNING**: 60초 타이머가 가며 카드가 스케줄대로 활성화된다. 미션 체인을 진행한다.
4. **BONUS** (open 모드, 실패 시 선택 노출): 취켓팅 10초 (§9).
5. **RESULT**: 칭호·원인·타임라인·공유.

## 4. 미션 체인

- 스테이지는 단계 목록을 순서대로 정의한다 (`steps`). 예(티켓팅): `open → queue → captcha → zone → seat → pay`.
- 단계는 **완료 조건**을 가진다 (예: `seat` = 좌석 1개 선점 성공).
- 단계 진행은 `active step` 하나만 존재한다. 단, deadline 모드의 병렬 과제는 `lanes`(독립 체인 N개)를 가질 수 있다.
- 되돌림(`resetStep`) 카드는 `active step`을 이전 단계로 돌린다. 시간은 되돌리지 않는다.
- 마지막 단계를 완료하면 **즉시 성공**한다. 60초가 다 차면 실패(`timeout`).

## 5. 정각 판정 (open 모드의 시그니처)

플레이어가 "오픈" 버튼을 누른 틱을 `t`, 오픈 틱을 `T0`라 하자. (시작값, 조정 대상)

| 조건 | 판정 | 효과 |
|---|---|---|
| `t < T0` | EARLY | "아직 오픈 전입니다" 16틱(0.8초) 입력 잠금 + 대기 순번 대폭 후퇴 |
| `T0 ≤ t < T0+3틱` (0~150ms) | PERFECT | 대기 순번 최상위권 |
| `T0+3 ≤ t < T0+12틱` (150~600ms) | GOOD | 대기 순번 상위권 |
| `T0+12 ≤ t < T0+40틱` (600ms~2s) | LATE | 대기 순번 중위권 |
| 그 이상 | SLOW | 대기 순번 하위권 |

- 대기 순번 숫자는 `판정 + queue 스트림 난수`로 정하고, 이후 틱마다 **결정적으로** 줄어든다. 순번이 0이 되면 대기 단계 완료.
- 시계가 정확하다고 보장하지 않는다: `wrong-clock` 카드가 있으면 화면 시계가 T0와 어긋난다 (플레이어는 소리/보조 신호를 믿어야 함).
- deadline 모드에는 정각 판정이 없다.

## 6. 카드 규칙

1. 카드는 스케줄의 `startTick`에 **텔레그래프** 상태가 되고, `telegraphMs` 뒤 **활성**이 된다.
2. 활성 카드는 `resolve` 조건을 만족하면 **해결**된다. 조건은 카드 데이터에 있다 (탭·입력·길게 누르기·건드리지 않기 등).
3. `activeMs`가 지나도 미해결이면 **실패 효과**를 적용하고 카드는 사라진다. `activeMs`가 `null`이면 해결될 때까지 유지되고 다른 진행을 막는 카드가 있다.
4. `wait` 카드는 **해당 대상을 건드리면 실패**다. `ignore` 카드는 해결 불필요, 건드리면 시간 손실.
5. 해결 보상: 없음이 기본이다. 단, **연속 해결**(콤보)은 결과 화면에서 "손이 빠른 사람" 같은 칭호 조건에 쓴다.
6. 조합·슬롯·쿨다운 등 배치 규칙은 `design/hazard-system.md` §5.

## 7. 입력 모델

- 엔진은 **논리 행동**만 받는다: `{ tick, action, target, value? }`
- 액션 종류(초안): `tap`, `hold`, `type`(문자열), `swipe`(방향), `open`(정각 버튼)
- 화면 좌표·터치 이벤트는 UI 층에서 대상 ID로 변환한다. 빗나간 탭은 **엔진에 전달하지 않는다** (UI의 몫이며 재미의 일부).
- 입력 로그는 판의 전부이다: `(seed, contentVersion, inputs[])` → 재현.

## 8. 점수와 등급

한 판의 결과 객체:

```ts
interface RunResult {
  outcome: 'success' | 'fail';
  reason: 'done' | 'timeout' | 'fatal' | 'earlyLock' | 'queueReset' | string;
  remainingTicks: number;     // 성공 시 남은 시간
  resolvedCards: number;      // 해결한 카드 수
  failedCards: number;
  synergies: string[];        // 발생한 조합 이름
  titleId: string;            // 결과 칭호 (콘텐츠 정의 참조)
  bonus?: { attempted: boolean; won: boolean };
}
```

- 별점(1~3): 성공이면 기본 1개, 남은 시간 ≥ 5초이면 2개, 실패 카드 0이면 3개. (시작값)
- 칭호는 **조건 우선순위 표**로 결정한다 (`stage.results`). 위에서부터 첫 일치.
- 점수 숫자는 두지 않는다. 비교는 "칭호 + 남은 시간"으로 한다 (공유 카드 단순화).

## 9. 취켓팅 보너스 (open 모드)

- 조건: 실패한 판 직후 노출 (건너뛰기 가능). 같은 판당 1회.
- 10초 동안 화면 여러 곳에서 "취소표" 슬롯이 짧게 깜빡인다. **깜빡임 위치와 시각은 시드로 결정**되며 탭하면 즉시 성공.
- 성공 시 칭호를 `bonus-win`으로 덮어쓴다. 성공 확률은 낮게 조정한다 (시작값 5~10%).

## 10. 튜토리얼 (난이도 0)

- 고정 스케줄(시드 무관). 해결 방법이 화면에 **직접 안내**되고, **안내대로 하면 반드시 성공**한다. 테스트로 고정한다.
- 카드 2개: 하나는 `ambient`(카톡 알림), 하나는 `overlay`(팝업 닫기).
- 실패 조건은 시간 초과뿐이며, 시간 여유를 넉넉히 둔다 (90초 기본).
- 튜토리얼을 마치면 첫 스테이지가 열리고 진짜 규칙(난이도 1)로 간다.

## 11. 시드와 재현 규칙 (요약)

- 시드 문자열 `"{stageId}|{difficulty}|{code}"`. 데일리 시드(`code = YYYYMMDD` KST)는 **1차에서 제외**(결정 0001), 형식만 호환 유지.
- 화면은 PC·모바일 반응형. 엔진은 동일하고 UI 배치만 다르다 (`spec/realism-spec.md` §0).
- 엔진·디렉터는 `Math.random`·`Date.now`를 사용하지 않는다. (린트 규칙으로 금지)
- 자세한 스트림·테스트는 `design/hazard-system.md` §6~8.

## 12. 저장 (localStorage)

키 이름은 `ibunjeon:v1:*` 접두 [이름 임시]. JSON, 스키마 버전 포함.

| 키 | 내용 |
|---|---|
| `profile` | 닉네임(선택), 설정(접근성), 튜토리얼 완료 |
| `progress` | 스테이지별 시도 횟수·최고 칭호·최고 별점 |
| `history` | 최근 N판 결과 요약 (시드·칭호·남은 틱). 용량 제한 때문에 N≤100 |
| `daily` | 마지막으로 플레이한 데일리 날짜와 결과 |

- 서버·계정 없음. 개인정보 수집 없음. 분석 도구 없음(기본).
- 저장 실패(용량·프라이빗 모드)를 가정해 앱이 정상 동작해야 한다.
